# Архитектура

## Что это

ВСЛУХ — тренажёр спонтанной речи. Пользователь выбирает темы, получает вопрос, готовится
фиксированное время и говорит вслух.

## Режимы

| Режим        | Подготовка | Речь    |
| ------------ | ---------- | ------- |
| `spontaneous`| 30 сек     | 60 сек  |
| `deep`       | 120 сек    | 180 сек |

Длительности заданы в `vsluh-backend/lambdas-go/common/domain` — это единственный источник
правды. Фронт дублирует их только для подсказок в интерфейсе.

## Сущности

| Сущность   | Ключи DynamoDB                      | Описание                                 |
| ---------- | ----------------------------------- | ---------------------------------------- |
| `Question` | PK `topic_id`, SK `question_id`     | Карточка вопроса, опционально с настроением |
| `Session`  | PK `user_id`, SK `session_id`       | Сеанс практики, TTL по `expires_at`      |
| `User`     | PK `email` (нормализованный)        | Учётная запись: `user_id`, имя, bcrypt-хеш пароля |

Темы (`Topic`) пока захардкожены в `funcs/internal/handler/practice.go` — редактура не нужна.
Когда появится админка, справочник переедет в DynamoDB.

## Компоненты

```
vsluh.club        Nuxt (статика, S3 + CloudFront)  →  лендинг и Telegram Mini App
api.vsluh.club    API Gateway → Go Lambda         →  REST API (заготовка)
                                    ↓
                                DynamoDB
```

Одна сборка обслуживает оба сценария: внутри Telegram приложение подхватывает `initData`
и подстраивает интерфейс, в обычном браузере работает как лендинг.

## API

| Метод  | Путь            | Назначение                           |
| ------ | --------------- | ------------------------------------ |
| `GET`  | `/health`            | Живость сервиса                      |
| `GET`  | `/v1/topics`         | Справочник тем                       |
| `POST` | `/v1/sessions`       | Старт практики (валидация параметров)|
| `POST` | `/v1/auth/register`  | Регистрация по почте и паролю        |
| `POST` | `/v1/auth/login`     | Вход, выдача токена сессии           |
| `GET`  | `/v1/auth/me`        | Профиль владельца токена и баланс    |
| `POST` | `/v1/credits/spend`  | Списать кредит за разбор речи        |
| `POST` | `/v1/checks`         | Разбор записи ответа, списывает кредит|
| `GET`  | `/v1/checks`         | История разборов, страницами по 20   |
| `GET`  | `/v1/checks/{id}`    | Один разбор со ссылкой на запись     |
| `GET`  | `/v1/stats`          | Статистика кабинета                  |

Тело и ответы — `snake_case`. Авторизация мини-аппа — заголовок `X-Telegram-Init-Data`
(Base64 от `initData`), подпись проверяется HMAC-SHA256 по токену бота.

## Аккаунты

Почта и пароль, без подтверждения адреса — его добавим, когда появится отправка писем.

- Пароль хранится только bcrypt-хешем, наружу не отдаётся никогда (`json:"-"`).
- Уникальность адреса держит `attribute_not_exists(email)` на записи, а не
  предварительная проверка: между чтением и записью возможна гонка.
- На незнакомый адрес и на неверный пароль ответ одинаковый — `401 invalid email or
  password`, иначе форма превращается в проверку, кто зарегистрирован.
- Токен сессии — JWT HS256 на 30 дней, подписывается секретом `AUTH_JWT_SECRET`
  (GitHub Secrets `USER_BACKEND_{DEV|PROD}_AUTH_JWT_SECRET`). Уходит в заголовке
  `Authorization: Bearer`, на фронте лежит в `localStorage` под `vsluh_token`.
- Секрет не задан — ручки входа отвечают `503`, остальное API работает.
- Форма входа на лендинге включается флагом контура `NUXT_PUBLIC_FEATURE_AUTH`:
  на dev — включена, на проде пока нет.

## Кредиты

Разбор речи платный: один разбор — один кредит.

- За регистрацию начисляем `domain.SignupCredits` = 3 кредита, и сразу после неё
  показываем поздравление с подарком.
- Баланс лежит в той же записи пользователя (`credits`) и приезжает на фронт
  вместе с профилем в `/v1/auth/login`, `/v1/auth/register` и `/v1/auth/me`.
- Списание — `POST /v1/credits/spend`: `UpdateItem` с условием `credits >= 1`,
  чтобы два параллельных разбора не увели баланс в минус. Ответ — остаток.
- Кредиты кончились — `402 not enough credits`. Фронт на этот ответ не показывает
  разбор, а предлагает пополнить баланс.
- Гостям разбор недоступен: сначала вход, потом списание.
- Разбор на лендинге включается флагом контура `NUXT_PUBLIC_FEATURE_ANALYSIS`
  (на dev — включён, на проде нет).

## Разбор речи

Запись ответа уезжает на бэк целиком, в base64, и разбирается за один запрос.

- Распознаёт `qwen-audio-3.0-asr-flash` в Alibaba Model Studio (Сингапур). Клиент —
  `common/ai`, туда же спрятано знание о форме ответа: результат лежит в `output.output`,
  тайминги слов приходят в миллисекундах.
- Метрики считаем сами в `common/analysis`: темп, слова-паразиты, повторы, длинные паузы.
  Советы — коды (`fillers_many`, `pace_fast` и прочие), тексты живут в локалях фронта.
- Текстовая модель (`DASHSCOPE_LLM_MODEL`) подключается отдельно: пока переменная пуста,
  совета от модели нет и показываются подсказки по правилам.
- Кредит списывается до обращения к модели и возвращается, если разбор не состоялся:
  за нашу поломку пользователь платить не должен.
- Запись больше 6 МБ — `413`, незнакомый контейнер — `422`, тишина — `422 no speech
  recognized` с возвратом кредита.

## История и хранение

- Записи лежат в приватном бакете `AudioBucket` бессрочно, ключ — `checks/{хеш почты}/{id}.{формат}`.
  Наружу отдаём временную ссылку (presigned GET на 30 минут), и только владельцу.
- Разборы хранит таблица `ChecksTable`: ключ — почта владельца, сортировка — `sort_key`
  вида `{время наоборот}#{id}`, то есть свежие сверху. Курсор истории — последний `sort_key` страницы.
- Статистика считается на лету по последним 500 разборам: суммы (минуты, слова,
  слова-паразиты), средний темп, паразиты на попытку, топ слов-паразитов, динамика
  по дням за месяц и серия дней подряд.
- Страница `/history` на фронте показывает обзор всех попыток и карточки: тема, время,
  запись, вердикт. Список уже содержит подписанные ссылки на записи, а полный отчёт
  (расшифровка, метрики, советы) приходит отдельным запросом при нажатии «Подробнее».
- Вердикт — оценка от 0 до 100, считается на фронте (`shared/lib/verdict.ts`) по уже
  измеренным метрикам: темп вне коридора 90–170 слов в минуту, паразиты, повторы и
  длинные паузы на минуту речи. Тексты уровней и подсказок живут в локалях.

## Валидация

Каждое ограничение живёт в двух местах:

| Правило                    | Фронт                        | Бэк                      |
| -------------------------- | ---------------------------- | ------------------------ |
| Минимум одна тема          | кнопка «Продолжить» неактивна| `422 at least one topic` |
| Тема существует            | выбор только из списка       | `422 unknown topic`      |
| Режим поддерживается       | переключатель из двух опций  | `422 unsupported mode`   |
| Пароль от 6 символов       | `minlength` в форме          | `422 password is too short` |
| Почта похожа на настоящую  | `type="email"`               | `422 invalid email`      |
| Почта свободна             | ошибка под формой            | `409 email already registered` |
| Хватает кредитов           | разбор не показываем         | `402 not enough credits` |
| Запись не пустая           | пустую не отправляем         | `400 invalid audio payload` |
| Запись до 6 МБ             | пишем 32 кбит/с              | `413 recording is too large` |
| Контейнер поддерживается   | формат выбирает браузер      | `422 unsupported audio format` |
| Чужой разбор недоступен    | списка чужих нет             | `404 check not found`    |
